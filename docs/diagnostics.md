# 问题反馈与故障记录

普通用户提供“电视型号、安卓版本、轻投版本、出错前做了什么、屏幕上的表现”就能帮助排查。缺少日志也可以反馈；日志能够进一步缩小原因范围。

## 在电视上查看

0.2.2-beta.1 起，主页右上角的「反馈」里增加「故障记录」。页面会列出设备信息、错误编号、发生时间、出错阶段和技术日志。遥控器可以逐页翻阅，用手机拍照后发送给开发者；也可以复制完整记录。

遇到能够捕获的启动错误，主页在前台时会显示故障页面。未处理的 Java/Kotlin 错误会尽量在退出前保存，下次打开时先显示记录。诊断页面使用系统基础控件，不会启动投屏服务。

应用在启动底层组件期间直接退出时，可能来不及保存堆栈。下次打开会显示“上次启动没有完成”和最后记录到的步骤。这条记录无法区分底层崩溃、用户结束应用和系统结束进程，也不会把推测当作原因。

系统强制结束进程、存储空间耗尽、安装阶段失败，以及启动阶段以外的底层崩溃，可能没有完整记录。页面没有记录时，仍可反馈设备信息和现象。

## 一份有用的反馈

| 信息 | 示例 |
|---|---|
| 电视或投影仪 | 天猫魔屏 S2 Pro |
| 系统与轻投版本 | Android 5.1.1，轻投 0.2.2-beta.1 |
| 发生步骤 | 安装成功，打开后约两秒退回桌面 |
| 出现频率 | 每次出现，重启后相同 |
| 投屏来源 | iPhone 型号、iOS 版本、使用的 App，以及镜像或应用内投屏 |
| 附件 | 故障记录各页照片；黑屏或断连可以补充操作录像 |

闪退发生在手机连接之前时，可以说明“尚未开始投屏”。照片里出现账号等个人信息时，可在分享前遮盖。

诊断记录仅保存在电视的应用私有目录，不自动上传。记录不收集播放地址、局域网地址、配对码或账号；异常消息中的常见 URL、IP、MAC 和凭据字段会做脱敏。完整日志仍应在发送前查看。

## 页面无法打开时

熟悉 ADB 的用户或协助安装的人可以使用电脑获取系统日志。电视需要开启 ADB 调试，并与电脑连接成功。记录出错的时间，复现一次后执行：

```bash
adb logcat -d -b crash -v threadtime > LiteCast-crash.txt
adb logcat -d -v threadtime > LiteCast-logcat.txt
```

部分旧电视没有独立的 crash 缓冲区，第二条命令可作为补充。系统日志可能包含其他应用信息，分享前应保留相关时间段并检查隐私。无需清除整台电视已有的日志。

## 开发验证

- `python3 tools/check_native_apk.py <apk>` 检查实际 APK 的每种架构，拒绝独立的 `libcrypto.so`、动态加密依赖和外露的加密符号。
- `./gradlew testDebugUnitTest lintDebug` 验证错误脱敏、异常原因链和 AirPlay 故障后的 DLNA 生命周期。
- `./gradlew -PwithX86 connectedDebugAndroidTest` 在模拟器实际加载原生库并打开界面；Android 5.x 测试先加载系统加密库，以覆盖同名冲突场景。
- GitHub Build 工作流包含 API 21、22、23、31 的实际 Android 进程测试，并保存故障页截图。

模拟器验证不代表天猫、乐视真机验证。正式发布前仍需使用 ARM32 设备测试冷启动、重启后接收、AirPlay 镜像、普通视频投屏及播放中断；索尼等新系统需要回归测试。测试结果应区分“已通过”“失败”和“待真机验证”。
