# 轻投 0.2.2

本次正式更新集中处理 Android 5.x 启动兼容性，并增加可拍照反馈的故障记录。最低支持 Android 5.0，暂未扩展到 Android 4.x。

## 用户反馈与定位

目前收到三类设备反馈，其中两类是 Android 5.x 启动闪退：

| 设备 | 系统与现象 | 本次处理情况 |
| --- | --- | --- |
| 天猫魔屏 S2 Pro | Android 5.1.1 / YunOS，打开后约 2–3 秒退出 | 根据 @scud3g 在 [Issue #4](https://github.com/Jaqennn/LiteCast/issues/4) 提供的日志和设备信息定位并修复加密库加载冲突风险，等待原设备确认 |
| 乐视 X3-40S | Android 5.0.1，小红书用户反馈启动闪退 | 纳入本次旧系统兼容处理；尚无崩溃日志，不能确认与魔屏属于同一原因，等待实机反馈 |
| 小米电视 3S | Android 6.0，后台发现、投屏断连及部分视频黑屏，见 [Issue #2](https://github.com/Jaqennn/LiteCast/issues/2) | 原有专项测试分支继续独立，尚未收到验证结果，本次未合并该分支，也未宣称解决这些问题 |

魔屏日志显示：`libairplay_native.so` 找不到 `EVP_CIPHER_CTX_reset`。结合旧安装包依赖检查，重点原因是旧版 Android 的动态库加载规则可能使应用加载到系统内同名的旧 `libcrypto.so`，导致缺少函数。这个判断来自日志和安装包分析，尚未在魔屏原设备上复现验证。

## 本次改进

- 将 OpenSSL 静态链接进 AirPlay 核心，并隐藏相关加密符号，去除对同名动态加密库的依赖。新增安装包检查，防止再次打包出此类冲突。
- 为底层库加载和 AirPlay 启动增加错误保护。AirPlay 启动失败时记录具体错误，DLNA 可以独立启动，并保持开关、资源释放和唤醒锁的生命周期正确。
- 新增「反馈 → 故障记录」：包含应用版本、设备型号、系统版本、错误编号和日志，支持遥控器翻页、手机拍照与复制完整记录。
- 可捕获的 Java/Kotlin 退出错误会尽量保存，下次启动展示记录；底层启动中断会保留最后阶段。系统直接终止进程或部分原生崩溃仍可能没有完整堆栈，页面会说明未知原因，避免凭空判断。日志仅保存在本机，不会自动上传。

## 测试范围

GitHub Actions 在云端 Linux 主机中启动安卓模拟器验证，使用 AOSP x86 / x86_64 系统镜像：

- Android 5.0.2 / API 21、5.1.1 / API 22、6.0 / API 23、12 / API 31。
- 检查底层库加载与 JNI 调用、主页启动、故障记录页面；Android 5.x 测试还预先加载系统加密库。
- 每个系统执行 3 项启动检查，以及 4 个跨进程记录保存与恢复测试阶段。记录恢复通过写入测试记录和强制停止进程验证。
- 47 项单元测试通过；15 项需单独启用的截图测试未运行。Lint 无错误，仍有警告。
- APK 原生依赖检查覆盖测试包的 ARM32、ARM64、x86、x86_64。正式包保留 ARM32 / ARM64，并再次检查依赖和正式签名。

上述模拟器验证覆盖软件启动与故障处理，无法替代厂商 YunOS、电视 ARM 芯片、硬件解码和局域网投屏环境。魔屏、乐视及其他电视上的 AirPlay 镜像、视频播放和长期后台运行仍需要实机反馈。

## 下载与更新

[直接下载 LiteCast.apk](https://github.com/Jaqennn/LiteCast/releases/download/v0.2.2/LiteCast.apk)，无需登录 GitHub。发布页下方 Assets 中也提供同一安装包。

- 使用原有正式签名，应用包名保持 `io.github.litecast`，版本号提升为 0.2.2 / versionCode 6。已安装同签名正式版的用户可直接覆盖更新，保留设置，无需卸载。
- 安装过 0.2.2-beta.1 调试包或早期不同签名测试包的用户，需要卸载该测试包后安装正式版，卸载会清除应用设置。
- 出现问题时，可在「反馈 → 故障记录」拍摄各页，连同发生前的操作、是否能进入主页和具体投屏方式一起反馈。[反馈说明](https://github.com/Jaqennn/LiteCast/blob/main/docs/diagnostics.md)。
