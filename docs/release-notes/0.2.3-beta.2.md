**[直接下载 LiteCast.apk](https://github.com/Jaqennn/LiteCast/releases/download/v0.2.3-beta.2/LiteCast.apk)**，无需登录。Assets 内选择 LiteCast.apk；Source code 是源代码。

## 反馈与修复

感谢 @scud3g 在 [天猫魔屏 Issue #4](https://github.com/Jaqennn/LiteCast/issues/4#issuecomment-6917627435) 的 Android 5.1.1 / API 22 / ARM32 复测：beta.1 开启「强制使用软件 AAC 解码」后，有声镜像持续 8 分 30 秒正常，原先音频到达即闪退的情况未再发生。仍有切换投屏黑屏、抖音换视频后旧声音残留和音画不同步待验证。

- Android 5.0/5.1 自动使用内置软件音频解码，绕过旧系统原生 MediaCodec 创建失败的危险路径，无需手动开启 AAC 开关。较新系统保持现有选择策略。
- 修复 AirPlay 音频 FLUSH 回调只记录日志的遗漏：清理旧解码状态与排队声音，保留清空边界之后的新声音。音频格式改变时同样重置缓冲。FFmpeg 输入包增加所需的零填充保护。
- 视频解码器启动失败后，间隔 300 毫秒自动重试，最多三次。限量保留首批视频数据，静止画面也能触发恢复；断开、分辨率变化或新会话会取消旧重试。重试耗尽时提示重新连接。释放解码器时，即使 stop 报错也继续 release。
- 镜像接入时结束正在播放的 App 视频。尚未对不同品牌硬解资源释放耗时作统一保证。
- 故障记录增加音频解码路径、首批 PCM、输出缓冲参数，以及每五秒的音频队列、目标缓冲、解码耗时、错误计数和时间戳。采样不执行 fsync，不记录媒体内容或播放地址。
- 反馈页移除腾讯问卷二维码，保留设备信息、故障记录和拍照反馈指引，可在 GitHub 提交 Issue 或通过社媒私信作者。

## 测试与适用范围

发布流程要求单元测试、Lint、原生线程与音频缓冲回归、Android API 21/22/23/31 模拟器测试通过。新增在模拟器上实际编码 AAC-LC/AAC-ELD，再用应用内置 FFmpeg 解码为非静音 PCM，以及异常音频输入测试。缓冲测试检查旧音频清除、新音频保留及连续播放顺序；重试测试检查自动恢复、取消和资源上限。

模拟器检查不等于天猫魔屏 YunOS ARM32 实机验证。音画不同步的全部原因尚未确认；本版不统一修改所有设备的音频延迟，也不保证抖音网络加载改善。

## 希望复测

1. 同一台 iPhone 开启屏幕镜像，播放图库内带说话或拍手的本地视频 5–10 分钟，观察声音与画面。请注明使用控制中心镜像，还是相册里的 AirPlay 按钮。
2. 同样通过屏幕镜像播放抖音，连续播放并切换几条视频，观察上一条声音是否仍残留、延迟是否随时间增加。与 App 自带投屏分别记录。
3. 有余力时检查视频投屏转镜像是否自行恢复，作为低优先级补测。
4. 异常发生后尽快拍摄「反馈 → 故障记录」各页，注明时间、操作、是否已恢复；如方便，可附对应 logcat。记录包含电视型号、Android/API、版本号和上述音频指标。
