## 修改内容

- 原生 AirPlay 工作线程通过 JNI 接入后，在退出时自动 Detach；检查接入失败，保留 Java 自有线程的生命周期。
- 服务器先停止并等待网络工作线程退出，再释放视频会话；工作线程自行退出后也必须完成等待。初始化失败时停止继续启动，避免半初始化对象进入连接流程。
- 补齐 /info 请求所需的 DNS-SD TXT 二进制数据。
- 保存连接接收、初始化、请求类别、播放与清理阶段。记录包含时间和线程号，不记录播放地址、配对密钥或请求正文，大小有限制。
- 下次启动可在「反馈 → 故障记录」查看上次进程留下的阶段，并查看当前运行阶段。阶段记录不是完整崩溃堆栈，正常进程结束也可能留下记录；不能仅凭记录判定发生崩溃。

## 验证与限制

发布流程要求单元测试、Lint、原生线程生命周期回归，以及 Android API 21、22、23、31 模拟器检查通过。

本轮新增真实本机 TCP/RTSP 请求测试：重复启动服务器、查询设备信息、快速断连、不完整请求、连接存在时停止及重复停止。保留原有启动、故障页与跨进程记录恢复检查。构建时验证原生加密依赖和正式签名，保存符号文件供后续定位。

模拟器测试不等于真实 iPhone AirPlay 配对、镜像、媒体播放或 YunOS ARM32 实机验证。两类实机崩溃是否消失仍待确认。

## 希望复测

1. 爱奇艺 AirPlay 是否仍然立即退出。
2. iPhone 屏幕镜像是否能连接、持续播放，并反复断开重连。
3. DLNA 播放、拖动进度和开机自启是否保持正常。
4. 如仍有异常，再次打开轻投后提供「故障记录」各页照片、完整 logcat 和触发步骤。若能取得原生 backtrace / PC 模块偏移，可结合对应符号定位；仅有 fault address 无法准确符号化。
